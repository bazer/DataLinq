## Failure And Cancellation Reconciliation

| Phase | Native server evidence | SQLite evidence and limit |
| --- | --- | --- |
| Before dispatch | Invalid capability/lifecycle precedes pre-cancellation. Pooled open cancellation and failed authentication are not command dispatch. Unused pre-canceled transactions remain reusable. | Validation/pre-cancellation and setup cancellation preserve the same admission rules. Awaitable open/setup need not suspend. |
| In-flight command | Tests observe the exact statement in the server process list under a native lock, then exercise caller cancellation, command timeout and hard cancellation. [Ordinary generated-read interruption](../../../../src/DataLinq.Tests.MySql/NativeAsyncReadInterruptionTests.cs) checks recovery even when the native connection survives. | Native lock failures retain actual SQLite error classification. Busy/locked is not automatically labeled Timeout, and token cancellation is not claimed to interrupt a synchronous native call. |
| Between rows / early exit | Raw and generated reader tests prove closure of owned readers/commands and subsequent standalone capacity. A transaction connection remains owned until completion/disposal. | Both modes verify between-row cancellation and independent settlement. Physical closure of a named-memory handle does not prove file-pool reuse. |
| Completion / recovery | A missing commit acknowledgement stays Unknown, including after a later rollback response. An independent cooperative recovery token retains exclusive ownership until actual settlement; timer expiration never permits abandoned I/O. | Commit authorization rejection stays Unknown after successful rollback. Expiration before rollback entry preserves the original provider error or exact caller token and the actual implicit-disposal rollback failure. It does not establish a hard wall-clock bound. |
| Cleanup / multiple failures | Native transaction disposal faults retain provider cause and ordered secondary failures. W1 controllable tests retain combinations that live native drivers cannot reliably expose. | Equivalent classification is bound at native disposal. The separately reproduced failed-rollback file-pool defect means disposed ADO state is insufficient to establish safe reuse. |

Two pinned-driver behaviors bound the reader-cleanup claim. [MySqlConnector reader disposal](https://github.com/mysql-net/MySqlConnector/blob/2.6.2/src/MySqlConnector/MySqlDataReader.cs#L556-L590) catches native errors while draining remaining results. [Microsoft.Data.Sqlite reader disposal](https://github.com/dotnet/efcore/blob/v10.0.11/src/Microsoft.Data.Sqlite.Core/SqliteDataReader.cs#L216-L248) also suppresses errors during its remaining-result loop. DataLinq preserves failures that escape those boundaries; no test claims that it reports exceptions the driver swallowed. These limitations differ from the actual transaction-disposal errors exercised above.

## Acceptance Status

The operation audit finds native bindings for each W2 family. The focused telemetry addition closes a previously missing native parity check. Acceptance remains conditional on:

1. Clean candidate functional evidence is now recorded in the [checkpoint](W2%20Functional%20And%20Performance%20Checkpoint.md): **8,539/8,539**, individual provider totals, matching clean source/runner and **ValidForEvidence=true** on `49176d7a`, with passing CI #623. The earlier paired-batch `fe70d481` receipt remains unchanged.
2. The six canonical performance lanes are captured and verified, with unchanged operation counts/telemetry. The [cost follow-up](W2%20Performance%20Cost%20Disposition.md) attributes additional mutation allocation to native coordination and diagnostics, retains the measured trade-off and removes a separate avoidable lifecycle factory allocation. Revised-candidate performance review, particularly cold-key latency, remains open. Fixed Memory/hot-path and later ABBA controls do not erase original warnings. The supplemental generated-getter probe quantifies W2's defensive-copy cost.
3. Adoption of the official SQLite ownership correction through `master` → `v0.10` → W2, followed by affected reruns. The separate [failed-rollback file-pool finding](SQLite%20Failed%20Rollback%20Pool%20Reuse%20Investigation.md) needs its own disposition; the ownership correction is not proof that rollback failure is fixed.
4. Honest retention of the earlier unexplained automatic-concurrency pool-reset/catalog timeouts and Linux allocation observation. Standard-budget functional/CI passes and the corrected measurement scaffold do not establish the original causes.

W3 owns public/generated signatures, packed/custom consumers and diagnostic exposure; W4 owns hosting/lifetimes/options; W5 owns startup comparison/policy. No such requirement is silently moved into this audit or represented as shipped behavior.
